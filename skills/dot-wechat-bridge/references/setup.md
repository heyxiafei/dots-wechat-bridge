# 安装与离线验证

## 先核对可执行范围

确认用户给出的源码目录、主机、现有实例和目标产品能力。使用原环境与包缓存，不复制依赖目录，不为升级另建消费者或重建绑定。只具备仓库读取能力时可以整理步骤，不能声称已经运行。

源码需要 Python 3.10+；桥接使用 `fcntl`，应按项目支持的 macOS 或 Linux 路径执行。长期服务方式、系统限额与平台入口以该版本文档及用户实际环境为准。本 Skill 不附带 tunnel-client，也不保证账号具备 Secure MCP Tunnel、私有插件或 MCP Events。

先检查锁定依赖文件、源文件和生成 schema 是否齐全，再运行该源码包的离线测试。已有环境可直接使用已确认的 Python：

```sh
python -m unittest discover -s probe_tests
python scripts/generate-schema.py --check
```

上述命令在已核实的源码根目录执行；`python` 代表选定解释器，不暗示系统默认 Python 足够。新环境需要安装依赖时，先检查 `requirements.lock` 和安装脚本；不要把需要下载依赖的 bootstrap 称为纯离线验证。合成测试只用临时数据库、假接口和必要的网络禁用保护，不读取生产状态作 fixture。

修改了源码、schema 或分发过程，就验证受影响路径及规定检查；已有冻结结果可核验哈希复用，不重复测试凑数。对源码压缩包应解压到隔离目录验证文件清单及可运行性；安装 Skill 只复制其目录到用户指定的 skills 位置，不会连接插件或部署桥接。已有同名 Skill 先比较，不能无条件覆盖。

## 首次接入的分阶段步骤

1. 准备可审阅配置与服务方案：专用私人隧道、owner-only、单实例、精确回调主机允许列表及原资源限额。MCP 工具侧没有逐调用者身份认证；微信 owner-only 不能代替隧道和插件的访问控制。
2. 由本人处理所需账号授权、隐藏输入运行密钥、扫码与手机确认。助手只使用文件引用，不读取密钥、OTP、二维码内容或私有完整日志。先确认是否已有可复用连接；新权限或持久访问需明确授权。
3. 经授权后运行已审配置，分别核对 health/ready、真实 MCP 只读调用、本人绑定。缺失平台能力时报告缺口，不借扩大权限、伪造配置或反复重连掩盖问题。
4. 持续接收依赖调用方支持 MCP Events。首次配置只建立一个获准的 `weixin.message` 订阅；升级保留既有订阅。只接受核实来源的精确 callback hostname，不使用通配符，不公开完整回调 URL 或签名。
5. 实际微信发送、Dot 写入和附件验收使用事先说明的无敏感样本与明确数量。每一项分别取得回执和本人收件证据；工具可用不代表后台持续处理已成立。

升级已有部署时改用 [运行与恢复](operations.md)，不要执行首次安装中的重新绑定流程。singletrial1 的首次镜像验收按 [单来源验收](single-source-trial.md)，不可用批量 enable 代替。

## 分发边界

仅导出固定清单内源码、测试、必要文档与许可证；不得带上 runtime、数据库/WAL、日志、二维码、真实消息、账号信息、私人配置、凭据、依赖二进制或旧私有 Git 历史。结合内容扫描和人工审阅，扫描无发现不等于绝对无敏感内容。

GitHub 目标仓库、可见性、写入范围和已有提交应先核实。目标不明确就交付无敏感包并报告缺项；不猜选仓库、新建公开仓库或改可见性。只有实际提交回执并读回对应版本后才报告上传完成。
