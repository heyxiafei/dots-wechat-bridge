# 迁移与功能验收

本候选以最新 R7 命令闭集诊断源码为基线，保留历史回归夹具和公开工具契约。迁移到新开发 Work 与生产服务切换分别记录。

## 覆盖与剩余缺口

|能力|本候选覆盖|真实环境状态/后续验证|
|---|---|---|
|本人文字双向|入站、事件、final、稳定ID与队列全部保留|旧实例有本人收件确认；新架构未据此宣称上线|
|菜单|目录/校验/展示分离，统一命令归一化|已知实际请求遭 `item_unknown_fields` 拒绝；缺新字段样本仍待定位|
|周额度|官方能力适配、可选本地App Server读取器、当前账户映射、四行展示与原final槽|可信宿主reader仍需实际接线，不能用本地fixture代替；官方客户端会话启动单独授权|
|复杂请求与附件|ack/final、原生图片/文件/视频、长图分页、引用完整性|新版本需逐件手机查看、文件打开和视频播放|
|dot镜像与固定ACK|历史账本、回退兼容源码保留|沿用原部署关闭/只读状态|
|AIHot|独立来源生产者、共享事件账本、微信/邮件消费者|独立状态需接续与核验；默认关闭，不补历史通知|
|运行恢复|独占锁、状态持久化、事件续期及安全安装入口|进程恢复、整机重启和断网分别验收|
|公开交付|固定清单导出、哈希、隐私、全量测试与CI|GitHub提交/PR与生产上线分别取得回执|

## 生产接续顺序

先在独立目录完成发布验证，冻结源码哈希与具体变更。随后只读核查现有服务入口、已安装源码、私有配置引用、绑定、原订阅、微信outbox及AIHot两渠道状态。记录用于对账的私有元数据，不把它们提交到仓库。

接续方案必须指定同一服务、同一私有状态目录、原writer退出证据、待发送/unknown处理、旧版本源码备份和回退入口。既有运行服务不因本开发副本生成而变化。只有具体接续获准后才停原实例、等待进程组退出和锁释放、替换源码，并用原设置启动一次。

新版本上线后依次核对健康状态、真实MCP工具、原订阅、全新本人消息的唯一处理与API状态，再取得本人手机收件确认。菜单、额度、媒体、AIHot微信和AIHot邮件逐项验证，不合并为一项“已恢复”。测试消息应是当前授权的无敏感样本。

AIHot 生产者与消费者必须读取同一已核共享账本，保留事件身份、授权代际与切点。若实际旧机离线或数据不可达，只记录已读取的迁移证据，等待确定接续来源。不要从旧日志重建一批待发消息。

## 回退

保留当前数据库与新记录，只恢复已冻结的旧源码及原安装回执；重启前仍确认唯一writer。不能把冻结测试夹具作为生产回退版本，不能覆盖当前账本或把unknown改回pending。回退后分别读回服务、订阅和队列状态。

## 验收记录模板

每项记录版本、测试环境、合成/真实类型、原稳定动作标识（仅私有记录）、结果、时间和证据来源。公开报告仅给脱敏结论。

- 源码验证：完整命令、退出码、测试数、失败/skip、schema与扫描。
- 已安装：源码哈希、单实例、原配置/状态接续。
- 接口状态：queued/accepted/rejected/unknown原样记录。
- 真实收件：本人明确确认及具体媒介，不由API状态推断。
- 未验项：命令字段样本、额度宿主、通知渠道、媒体或重启分别列明。
