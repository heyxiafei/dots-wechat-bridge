# 订阅期限与无到期契约

此文描述候选实现，不代表真实平台订阅已经续期或改为无到期。订阅期限、runtime key 到期、本地 `hard_stop_at` 是三个独立条件；无到期订阅不延长后两者。

## 正式请求与响应

遵守 [OpenAI MCP Events 的刷新契约](https://developers.openai.com/plugins/build/mcp-events#refresh-a-subscription)：

- 省略 `ttlMs`：使用服务器默认有限期限（24 小时）。
- 明确 `ttlMs:null`：请求无自动到期；服务端批准时才持久化 NULL 并返回 `refreshBefore:null`。
- 有限正整数：返回有限期限。保留现有 24 小时上限和 1 秒最低期限；除协议允许的最低期限外，不超过请求时长，不将有限请求升级成无期。
- 布尔值、非整数、非正数：拒绝，不改变原订阅。

服务端支持无到期不证明 ChatGPT 会发出该请求。没有文档化的 force-renew 工具时，不通过重复建自动化、虚构调用、修改数据库或读取私有平台数据来替代请求。平台正常刷新应使用同身份的 `events/subscribe`，保持 callback、事件名、arguments 和原订阅 ID。有限订阅仍需要在 `refreshBefore` 前真正续期。

## 迁移和安全边界

候选启动迁移仅让到期列支持 NULL，并保留原有限期限、订阅 ID、验证与签名轮换字段；不会把既有订阅自动置为无到期。迁移必须事务性完成，失败不得留下半迁移表或丢失关联。所有有效性判断，包括状态、排队、投递、单订阅检查和 supervisor，统一理解 NULL 的无到期语义，并保留事件名、身份过滤的括号优先级。

无到期仍可撤销。`events/unsubscribe` 删除原订阅并取消待投事件；当前版本的 callback 410 使该订阅失效。续租期间已经在途的旧投递不能撤销更新后的订阅。签名、公网地址、TLS、精确 host、owner-only、单实例和原发送去重均保持。

本人微信事件的自然 TTL 到期与明确撤销分开：仍保留同 ID、同事件名、已验证记录且 `0 < expires <= now` 时，原 queued 微信事件暂停，ID、正文、attempts、next_at 与 lease 不变；不阻塞其他可投事件。原调用方通过公开协议刷新同 ID 后恢复投递；过期记录不复用 300 秒挑战缓存，须重新通过已有 callback 验证。安装器不自动续期，过期启动回执明确为 `expired_requires_same_id_refresh`，不是有效订阅恢复。缺失订阅、unsubscribe 或 410（expires=0）保留取消行为，已取消/失败的历史不被重排或恢复；其他事件的原到期语义不变。

监督进程每次检查读取当前有效订阅，仍要求恰有一个本人 `weixin.message` 订阅，并独立遵守原 `hard_stop_at`。无到期不会新增后台服务、模型轮询或凭据。

## 部署与真实验收

须取得对原服务短停、源码/schema 迁移、重启和回滚的明确确认后才部署。先在隔离候选完成全部离线测试、schema 检查及独立审阅；队列空闲再使用一致私有备份并迁移唯一实例。不创建第二个订阅，不改 runtime key 或安全截止。

真实无到期验收必须同时看到：原平台实际 `ttlMs:null` 请求、成功 `refreshBefore:null` 响应、原订阅 ID 未变、有效本人订阅数量仍为 1。现有诊断只允许固定期限类别和批准布尔元数据，不能记录 callback 完整 URL、secret、签名或原始 RPC。持久化 NULL 本身不能作为平台已请求或已接收响应的全部证据。

## 回滚

部署后尚未批准任何无期记录时，可换回兼容旧代码；nullable schema 中的原有限值仍可被旧查询读取，多出的兼容字段不应影响旧显式列操作。不要为回滚恢复旧整库而覆盖期间的新消息、发信记录或镜像回执。

一旦存在无期订阅，不能直接启动旧 worker 或旧 supervisor：旧查询会把它当作失效。应先通过同身份正式 `events/subscribe` 请求有限 TTL，核验实际有限 `refreshBefore` 和新期限后再回滚；若没有受支持的原平台入口，保留兼容版本并报告阻塞，不能偷偷给数据库填入新期限。需要恢复 NOT NULL 约束时也必须确认所有期限均有限，并使用事务性迁移；无期记录存在时应拒绝降级。已失效或解除的订阅不能靠还原旧数据库复活。
