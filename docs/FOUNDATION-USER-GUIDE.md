# 底座候选使用说明

本轮交付是独立分支的可运行离线候选，不是已经接管微信的服务。现有绑定、DoT入口、菜单和发送账本继续使用原路径；无需为查看候选重新扫码。Python要求与原项目一致，3.10+，验证使用3.11。

## 一个入口

在源码目录、已有隔离Python环境中运行：

```sh
python -B -m foundation doctor --config config/foundation.json.example
python -B -m foundation demo --state /tmp/wechat-foundation-demo/tasks.sqlite3 --text '测试底座'
python -B -m foundation status --state /tmp/wechat-foundation-demo/tasks.sqlite3
```

doctor只检查结构与已配置模块，不读API Key、不联网、不查余额；默认DoT为BLOCKED，因为新包未注入原宿主。关闭全部后端仍可自检，启用状态不等于真实连接。

demo只使用合成本地回显，输出明确标记simulation、wechat_sends=0。重复相同message-id会命中持久防重，不重复生成回复；更换测试消息需显式 `--message-id synthetic-second-message`。不要把生产state传给demo。status使用只读数据库连接，查看时不会把另一个在途任务改成unknown。

停止demo只需等待一次命令结束；没有常驻服务或后台模型任务需要关闭。回滚候选是弃用本地分支；不要删除生产数据库或当前真实消息账本。

## 真正接入前的配置

复制 `config/foundation.json.example` 到自己的私有配置目录。默认后端为dot，其他后端关闭。API条目只填已获准模型ID、有限超时/输出量和凭据环境变量名，不填密钥值。`enabled=true`只使模块可选；实际网络仍须宿主在获准调用时显式允许，配置文件本身不能购买额度或授权付费。

五家供应商的真实请求/解析和mock测试已实现，接口、参数差异及缺失能力见PROVIDERS.md。它们目前是文本聊天，不能执行命令，也不能继承DoT的工具、任务、记忆或订阅福利。凭据、API余额、区域和模型访问权限需实际核验；本轮没有付费实调。

原微信宿主需注入真实owner读取、本人绑定证据、后端和原final发送接口，才能使用 `ExistingWeixinChannel` / `BridgeCore`。它们不会发现或复制微信token。新通道没有第二个poller、扫码或iLink发送器。宿主接入条件见HOST-BACKENDS.md。

## 管理命令（只在新路由真正接线后生效）

|命令|实际行为|
|---|---|
|`/status`|查看默认后端、模型和配置版本|
|`/backend <已注册ID>`|更新之后新任务的默认路由；不迁移已运行任务，也不宣称后端已连通|
|`/model <模型ID>`|只改变之后新任务；供应商仍会检查实际访问权限|
|`/new`|仅支持会话能力的后端更新会话映射；不支持者明确返回unsupported|
|`/stop <任务ID>`|仅调用原任务后端声明的取消接口；不支持、未确认或结果未知分别保留|

这些命令由确定性逻辑解析，并且先核本人、完整性、原消息和原final。附件或引用里的命令不能改变路由。初版引用消息有明确限制，不代表已支持所有上游能力。

旧 `/help` 和“额度”继续由原协调者处理。新候选没有把这些生产命令切到另一模型。“额度”最近实测未恢复，不能用本地token统计代替官方Codex周剩余比例和重置时间。

## 错误、费用与数据

任务状态、模型结果、原发送状态和手机收件分别记录。网络后果不确定为UNKNOWN，不自动重试或切换厂商；取消观察不等于官方调用已结束。一次任务绑定后端/模型/config版本，换默认不会把一半任务交给另一家。

API回执中的token用量按已返回字段记录，缺值未知。初版只有请求输入/输出与超时限制，没有账户级日/月结算预算控制；不显示估算金额为真实账单。每日/月预算、工具费用、ASR/生成成本与账单核对是后续明确任务，不宣称已实现。

后端会话ID分开保存，默认不转移完整聊天历史、附件或长期记忆。新SQLite只存路由/任务结果与状态，需使用私有目录；正文保留期/导出/清理的管理策略仍需后续完善。当前没有公网或无鉴权管理入口。

生产接续与回滚的精确步骤见FOUNDATION.md；正式执行前需核当时实际安装、单消费者证据、授权和备份，不能因源码可导入就启动第二消费者。
