# 用户操作说明

连接完成后，在原微信桥接聊天中直接说需求。每次结果以手机实际看到的内容为准。当前候选的线上缺口见 [MIGRATION.md](MIGRATION.md)。

|想做的事|怎么说|
|---|---|
|查看菜单|`/help`|
|查当前 Codex 周额度|`额度`、`查额度`、`查一下额度`|
|处理图片或文件|发文件，并说明“帮我检查这份内容”等需求|
|接着上次的问题|引用消息并补充；引用不完整时贴出关键文字|
|查看任务进度|直接问“进度怎么样”|
|把 dot 结果发到微信|在 dot 中明确说“把这份结果发到我的微信”|

简单问题通常只有一条完整回答；复杂工作可能先有进度、再有结果。额度缺工具、缺账户映射或字段不可用时会显示未知，不能拿旧额度代替当前数值。

微信侧只支持本人私聊，不支持群聊。语音仅使用微信上游已有转写；没有转写时需要补发文字。图片、文件、原生视频分别走附件传输；长图可能需要分块查看，超出限制时可在 dot 上传。

## 没收到时

先在 dot 说明发送时间和问题类型，让助手查询原发送状态。`queued` 是等待处理，`accepted` 是接口接受，`delivery_unknown` 是结果不确定。不要连续补发相同操作；保留原消息与发送记录供对账。

菜单没有触发时，保留该条请求的诊断类别；不要把“能够普通聊天”当菜单和额度都可用。新版本上线后分别验证 `/help` 和一条额度请求。

## AIHot 通知

AIHot 集成用于已有监控事件的微信/邮件通知。来源确认、通知启用、渠道投递、本人收件分别记录。新安装默认关闭；接续旧部署保留原未来切点、消费与去重记录。启用通知不等于转发历史事件。

邮件与微信相互独立，一个成功不代表另一个成功。来源停更或缺证据时显示待确认，不凭预计时间编造“已经重置”。

## 更换电脑或升级

先迁源码并验证，再核对旧服务是否仍在运行。运行密钥、账号绑定、数据库与订阅由原实例接续；本人扫码与凭据输入只在私有界面完成。新源码目录准备好不表示已经切换服务。
